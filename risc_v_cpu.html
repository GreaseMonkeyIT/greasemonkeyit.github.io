Overview

A Full RISC-V Core, Built from First Principles

A complete RV32I single-cycle processor implemented in SystemVerilog at the Register-Transfer Level. Every logic block: ALU, control unit, register file, sign extender, memory interface, load/store decoder, and reader; was written, simulated, and verified independently before assembly into the full datapath.

This was built following the Holy Core open-source RISC-V tutorial by BRH(GitHub:0BAB1), with an extended implementation adding full branch support, all jump types (JAL/JALR), LUI, AUIPC, and byte/halfword memory access. The design was synthesized with Yosys and the resulting netlist verified against the simulation model.

A Brief Introduction

What is a Single-Cycle Processor?

A single-cycle processor is a CPU architecture that executes an entire machine instruction in exactly one clock cycle. Unlike the processor powering your laptop or smartphone—which relies on complex features like pipelining to juggle multiple tasks simultaneously for maximum speed; a single-cycle core completes just one instruction at a time. It fetches the instruction, performs the necessary calculations, and saves the result in one continuous, uninterrupted sweep before the clock ticks again. The datapath is entirely combinational from fetch to write-back, with only the Program Counter (PC) and the register file being clocked.

While you wouldn't use this design to run a modern operating system, it is the essential starting point for computer architecture because it strips away overwhelming complexity to reveal exactly how hardware routes data and makes decisions. Beyond acting as a foundational proof of concept, this architecture still holds real-world value today. Because it is so straightforward, it is still ideal for prototyping and learning devices like digital calculators and simple embedded controllers.

Module Breakdown

8 Independent Blocks

src/control.sv
Control Unit
Decodes op, f3, f7 and the ALU flags into 8 control signals: alu_control (4-bit), imm_source (3-bit), mem_write, reg_write, alu_source, write_back_source (2-bit), pc_source, second_add_source (2-bit). Handles all RV32I branch conditions and jump types.
src/alu.sv
ALU
4-bit control word selects ADD, SUB, AND, OR, XOR, SLL, SRL, SRA, SLT, SLTU. Outputs 32-bit result plus zero flag (for BEQ/BNE) and last_bit (for BLT/BGE/SLTI/SLTIU). Fully combinational.
src/regfile.sv
Register File
32 × 32-bit registers, x0 hardwired to zero. Two asynchronous read ports (rs1, rs2), one synchronous write port (rd). Write-enable gated by both reg_write and wb_valid from the reader.
src/signext.sv
Sign Extender
3-bit imm_source selects immediate format: I-type (12-bit), S-type (store offset), B-type (branch target), J-type (JAL offset), U-type (LUI/AUIPC upper 20 bits). All sign-extended to 32 bits.
src/memory.sv
Memory
Parametric word-addressed memory with byte_enable[3:0] for sub-word writes. Used twice: as instruction ROM (write-enable tied low, init from .hex) and as data RAM. Misaligned access triggers $fatal.
src/load_store_decoder.sv
Load/Store Decoder
Takes ALU result address and f3 to compute the byte_enable mask and correctly-aligned write data for sb, sh, and sw stores. Handles byte-lane shifting for sub-word stores.
src/reader.sv
Reader
Extracts and sign-extends loaded data from the raw 32-bit memory word. Handles lb (sign-extended byte), lbu (unsigned byte), lh, lhu, and lw. Outputs valid to gate the write-back.
src/cpu.sv
Top Level — cpu
Wires all modules together. Contains the PC register and the four muxes: ALU source, write-back source (4-way), PC source (branch/jump), and second-adder source (PC-relative branches, absolute jumps, JALR, AUIPC).

Testbench Pattern

# test_alu.py — per-module Cocotb testbench
import cocotb
from cocotb.triggers import Timer

@cocotb.test()
async def test_add(dut):
    dut.alu_control.value = 0b0000   # ADD
    dut.src1.value        = 0x0000_0005
    dut.src2.value        = 0x0000_0003
    await Timer(1, units='ns')
    assert dut.alu_result.value == 8
    assert dut.zero.value       == 0
Synthesis

Yosys RTL Synthesis

The design was synthesized using Yosys open-source synthesis suite. sv2v first flattens the SystemVerilog package references into plain Verilog, then yosys proc elaborates the hierarchy — keeping named submodule instances intact rather than resolving to gate primitives. The JSON netlist is then rendered to SVG by netlistsvg and the diagram above is the unmodified output. 

# 1. Flatten SV packages → plain Verilog
sv2v packages/holy_core_pkg.sv \
     src/alu.sv src/control.sv src/regfile.sv \
     src/signext.sv src/memory.sv \
     src/load_store_decoder.sv src/reader.sv src/cpu.sv \
  > cpu_flat.v

# 2. Elaborate (proc level — keeps submodule hierarchy)
yosys -p "read_verilog cpu_flat.v; \
           hierarchy -check -top cpu; \
           proc; \
           write_json cpu_rtl.json"

# 3. Render to SVG
netlistsvg cpu_rtl.json -o cpu_netlist.svg
