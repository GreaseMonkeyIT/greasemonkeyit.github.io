Context

The Problem

During the internship at Cummins Turbo Technologies, the turbocharger test cells operated on an Allen-Bradley MicroLogix 1400 PLC. The PLC held hundreds of data registers: bit flags, integer counters, float measurements, timer accumulators; the like, spread across multiple SLC-style data files.

The plant was a small dedicated turbocharger manufacturing and engine remanufacturing facility with no SCADA system for its PLCs. Engineers had no remote visibility into live tag values, and fault diagnosis meant manually cycling through the script file to identify which tag had failed and what the register state was. There was no way to label, group, or log tags by product line or station, and writing a test value required navigating the PLC programmer software by hand.

The goal was a lightweight, self-contained SCADA stack: read all tags continuously, expose them over a REST API, and give both a GUI and a CLI for live inspection and writes; without requiring any proprietary SCADA platform.

System Design

Architecture

The stack has four components. The tag server is the core. It owns the in-memory tag store, probes the PLC on startup and at regular intervals, and serves a REST API. The bridge provides continuous 2-second diff-and-push sync between the PLC and the server, filling the gaps between server probes. The GUI and CLI (for headless setups) are independent clients that talk only to the REST API.

Implementation

Component Breakdown

01 — Core
tag_server.py
Flask REST server backed by waitress for production. Probes all data files synchronously on startup — before accepting any requests — to eliminate a race condition where the server was reachable but the tag store was empty. Tags are persisted to JSON with atomic file writes (write → .tmp → os.replace) so a crash mid-write never corrupts the store.
02 — Sync
plc_to_rest_bridge.py
Continuous PLC → server sync at 2-second intervals. Reads all monitored tags, diffs against last known state, and PATCHes only changed values to the REST server. Wrapped in an outer reconnect loop — if the PLC drops the EtherNet/IP connection, the bridge waits a configurable delay and retries without operator intervention.
03 — GUI
scada_gui.py
Tkinter application with two tabs. The Tag Page shows all discovered tags in a sortable treeview with group filtering (Product:Station). The I/O Control panel shows 20 discrete inputs as read-only indicators and 12 outputs as clickable toggles. Both are polled from the REST API every second — no direct PLC connection required.
04 — CLI
scada_cli.py
Interactive terminal menu for listing, reading, writing, labelling, and grouping tags. Handles bool/int/float/string parsing so writing true, 1, 450, or 3.14 all resolve to the correct Python type before the POST request. Also exposes a server health check showing PLC connection status and last probe timestamp.

Key design decisions

Threading safety — file I/O outside the lock
Tag metadata (descriptions, groups) is saved to disk inside save_tag_metadata(). The function takes a snapshot of the tag dict inside tags_lock, then releases the lock before writing — so disk I/O never blocks API request handlers waiting to acquire the lock. Readers are never blocked by a slow write.
waitress over Flask dev server
Flask's built-in dev server is single-threaded and not suitable for concurrent requests from the bridge, GUI, and CLI running simultaneously. waitress is a production-grade multi-threaded WSGI server that drops in with one import. Zero config change to the Flask app.
Tkinter startup — deferred initial load
The initial tag fetch and output state sync are deferred via after(0, _initial_load) rather than called directly in __init__. This lets the Tkinter window render fully before the first blocking network call runs. Without this, the window appears frozen until the PLC responds.

PLC Data Files

SLC Tag Address Format

The MicroLogix 1400 uses the same data file addressing as the SLC 500 instruction set. Each data file has a letter prefix, a file number, and an element index. Sub-elements like .ACC and .PRE are addressed with dot notation.
